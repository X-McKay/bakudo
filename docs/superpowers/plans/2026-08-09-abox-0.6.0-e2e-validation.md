# abox 0.6.0 End-to-End Validation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove (or fix-then-prove) that the meta-redesign merged in PR #25 actually works end-to-end against the real abox 0.6.0 binary and the live homelab infra, with every change tracked on `validate/abox-0.6.0-e2e` for review.

**Architecture:** Phased validation with the smallest fix set that unblocks each phase ("gate fixes"). Everything the review found that is *not* required to run e2e gets filed as a GitHub issue in Phase 6, not fixed here. Companion review: `docs/superpowers/reviews/2026-08-09-post-refactor-review-findings.md` (finding IDs like ABOX-1 refer to it).

**Tech stack:** Python 3.11+/3.12, abox 0.6.0, Temporal 1.29.1 (`temporal.almckay.io:7233`, ns `bakudo`), Postgres 17 + pgvector, Neo4j 5.26, vLLM endpoints (`llm`/`llm-fast`/`embeddings` `.almckay.io`).

## Global constraints

- Branch: all changes on `validate/abox-0.6.0-e2e`; PR to `main` at the end.
- Secrets: values live only in git-ignored `.env` (chmod 600). Never echo values to stdout/argv/logs — export into env and consume via `os.environ`; print key names + char counts only.
- The stale Rust binary `~/.cargo/bin/bakudo` shadows the Python CLI: use `python3 -m bakudo.cli` everywhere, or remove the stale binary first (operator choice).
- Live cluster is shared: use throwaway identifiers (`run_id`s prefixed `run_E2E`, memory scope `{"repo":"e2e-validate"}`, Temporal workflow ids prefixed `e2e-`), and clean up rows/nodes/workflows created by tests.
- Model spend: live-model runs are bounded to single-turn explore/optimize runs with `--timeout ≤ 600`; no unattended loops (MEM-6 makes the observer loop unsafe to leave running).
- Every fix lands with a test that pins the *correct* behavior (the review showed wrong-protocol tests are worse than none).
- Commit per task with `git commit` (no `--no-verify` needed on this branch — `make check` is green).

## Decision points (answer before kickoff)

1. **Fix scope** — Recommended: only the gate fixes listed per phase (ABOX-1..5+8, TMP-1..4+7, API-2, plus MEM-embedder if #2 says yes); file the other ~50 findings as issues. Alternative: also fix all blockers/majors on this branch (roughly doubles the work and the review surface).
2. **Embedder** — Recommended: wire a real OpenAI-compatible embedder (small, contained change; makes Phase 4 a true semantic-memory validation against `embeddings.almckay.io`). Alternative: validate with the 256-dim HashingEmbedder as-is and file MEM-1.
3. **Infra** — Recommended: validate against the live homelab cluster (compose stack cannot run sandboxes anyway, TMP-13). Alternative: bring up local compose for Temporal/PG/Neo4j and only use live vLLM.
4. **Meta-agent autonomy checks** — Phase 3 stops at single-workflow validation (recommended); running the observer→meta-agent autonomous loop live is explicitly out of scope until MEM-6/TMP-3 are fixed properly (not just gate-patched).
